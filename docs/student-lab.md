# 學生實作｜先執行、再閱讀、再修改

## 練習一：先跑出完整成果（必做）

1. 依 README 執行 demo 指令，開啟產生的 HTML。
2. 用 expected-results.md 核對數字與第一項待辦時間。
3. 找到原始資料中的衝突行程與未安排待辦，說明原因。

完成證據：HTML 與 JSON，不只是一張終端機截圖。

## 練習二：看懂設計，再修改兩項偏好（必做）

1. 先讀 design-example.md，再複製 design-template.md 為自己的設計單。
2. 複製 data/demo.json 為 data/my-week.json，保持虛構人物。
3. 將 windows 改成 `[["10:00", "12:00"], ["14:00", "18:00"]]`。
4. 將 workdays 改成 `[0, 1, 2, 3, 4, 5]`，允許週六安排待辦。
5. 請 Agent 沿用現有工具處理新檔案，輸出至 output/my-week。

請求範例：

> 請使用 weekly-assistant，處理 data/my-week.json，週一起點 2026-11-23，輸出至 output/my-week。沿用現有程式，告訴我偏好改變後有哪些安排不同。

完成證據：原設定與新設定的結果比較，以及設計單上兩項變更。

## 練習三：讓 Agent 產生一段程式並驗證（必做）

先看懂 planner.py 的衝突判斷，再請 Agent 在 exercises/overlap_demo.py 另存一個可執行示範，不覆寫完整範例。

> 請寫一個 Python intervals_overlap 函式，用含時區的 datetime 判斷兩個行程是否重疊。前一個結束等於後一個開始時不算。附上重疊、相鄰、完全分離三個可執行驗證案例。存成 exercises/overlap_demo.py，實際執行並說明結果。

比較生成程式與 planner.py 的判斷，指出哪個規格避免了相鄰行程誤判。

## 練習四：替換素材並再次產出（必做，可沿用現圖）

1. 閱讀 assets/image-prompt.md。
2. 若具備生圖能力，請 Agent 產生自己喜歡的報告橫幅，先預覽，再另存舊版並替換 banner.png。
3. 若無生圖能力，沿用隨附圖片，說明它如何從 assets 被嵌入 HTML。
4. 重新執行程式並確認報告中有圖片。舊 HTML 嵌入的是舊圖，必須重跑才會更新。

完成證據：素材檔案、提示詞或沿用說明，以及實際報告。

## 練習五：透過 Skill 換一週資料（必做）

請 Agent 使用 second-week.json、週一起點 2026-11-30、輸出 output/second-week。應得到 2 行程、0 衝突、2 已安排、0 未安排。

對 Agent 提問：哪些檔案被重用？哪些是這次新產生？若每次重寫 Python，是否還是在使用同一個 Skill？

## 練習六：進階擴充（選做）

擇一進行，先更新設計單與規則，再修改程式與測試：

- 固定行程前後保留 15 分鐘交通緩衝。
- 依待辦類型設定不同時段，例如閱讀只排晚上。
- 允許長待辦切成多段，定義最短區塊與驗收方式。

這些行為目前沒有實作，不要只修改文字就宣稱支援。增加功能後需換資料核對。

## 繳交清單

- 填寫完成的設計單。
- 修改後的 Skill 或資料與素材。
- HTML 與 plan.json。
- 一項變更／問題 → 修改位置 → 重跑結果的紀錄。
