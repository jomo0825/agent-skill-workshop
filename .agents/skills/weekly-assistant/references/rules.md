# 輸入格式與排程規則

## JSON 格式

見專案根目錄 `data/demo.json`。所有欄位必填，額外欄位目前忽略。

- `person`：非空字串，顯示名稱。
- `preferences.workdays`：0 至 6 的不重複整數清單，0 為週一。
- `preferences.windows`：每日可安排待辦的時段，例如 `[["09:00", "12:00"], ["13:00", "18:00"]]`。同日、非重疊；不支援跨午夜時段。
- `events`：固定行程清單。每項為唯一 `id`、`title`、`start`、`end`。時間必須是含 UTC offset 的 ISO 8601，教學資料使用 `+08:00`。
- `tasks`：待辦清單。每項為唯一 `id`、`title`、正整數 `minutes`、`priority`（high / medium / low）、`due`（含 UTC offset 的時間）。

## 可解釋的教學演算法

1. 一週從指定週一 00:00 開始，至下週一 00:00 結束。顯示與每日可用時段固定採 UTC+08:00，輸入的其他 offset 會轉換。這個範例不處理夏令時間地區。
2. 固定行程原樣保留。只有與該週相交的行程進入報告。兩行程相交條件為 `a.start < b.end and b.start < a.end`；一個結束時另一個開始不算衝突。
3. 從每日可安排時段扣除所有固定行程，包含跨日與跨週邊界的行程。午休等不在 windows 內的時段，不會被用來安排待辦。
4. 待辦依優先級、期限、id 排序，依序放入期限前最早能完整容納的空檔。待辦不拆分；結束時間等於期限可以接受。
5. 期限早於本週起點的待辦標記為已逾期；本週無合適空檔則列為未安排。期限在未來週的待辦仍可提早安排在本週。
6. 不移動既定行程、不聲稱最佳化、不加入交通時間。這是可閱讀的貪婪演算法，適合教學；限制與未安排原因必須呈現給使用者。

## 輸出

- `plan.json`：固定行程、衝突、建議安排、未安排項目及摘要數量。
- `week-plan.html`：包含嵌入影像、每日時間表及提醒；可直接離線開啟。
- 輸出同名檔會被覆寫，請為不同使用者或測試指定不同 `--out`。
